# UI audit: what the page does and does not carry

Recorded from a screen recording of the deployed site on 4 November 2026, against two
reference sites the owner pointed at. This note states what is wrong, why the
references read as finished while we do not, and what the fix is.

## What the owner asked for, in his order

1. Stop naming Yahoo in product copy. The product is provider neutral.
2. Teams: show the fantasy league name, not only sport and season.
3. Teams: the row layout does not hold together, and the pause control is not aligned.
   Make the pause a small icon button beside the lineup checks toggle, with the full
   sentence in a tooltip.
4. Team detail: the same layout problem, and the same header problem.
5. "Report a problem with this team" should carry the team, not open a blank form.
6. Team detail: recent activity belongs at the top.
7. Team detail: the roster adds nothing. Remove it from the page and clean out the
   code that exists only for it.
8. Owner note: no warning about secrets, and no validation refusing a note that looks
   like a credential.
9. Owner note: the help text wraps early in a wide column, and "Up to 2,000 characters"
   is redundant against the counter.
10. Every team should offer a jump out to the provider, generated provider-neutrally.

## What the references actually do

Both are two tone, flat, and mostly monospace. The font is not the lesson. These are.

|                  | latentpatterns.com                | overalls.dev                        | Lineupkeep today                            |
| ---------------- | --------------------------------- | ----------------------------------- | ------------------------------------------- |
| Reading measure  | 720px                             | 720px                               | about 1150px                                |
| Body type        | 20px / 1.4                        | 16px / 1.5                          | 14 to 15px, grey                            |
| Page title       | 30px / 700                        | 32px / 800, caps                    | 32px / 600                                  |
| Rules            | one boxed button, one dark banner | hairlines between every header cell | one hairline under the header               |
| Surfaces         | none, flat background             | none, flat background               | boxed cards with their own borders          |
| Emphasis         | one dark block per screen         | one solid button, one dashed strip  | bold and link colour on five or six items   |
| Chromatic budget | ink on warm grey, one accent      | black on off white, one accent      | violet accents, gold, blue links, grey meta |

The pattern worth naming: **the references spend their contrast in one place**. A
single dark banner, a single solid button, a single illustration. Everything else is
one weight and one colour. Our pages spend contrast in a dozen small places, so nothing
reads as more important than anything else.

Two more things the references do that we do not:

- **A grid you can see.** overalls.dev draws its header as a table with hairlines. That
  is the entire visual idea, and it costs one border rule. Our teams list has no row
  separators, so six teams read as one grey smear.
- **A measure short enough to scan.** At 1150px our paragraphs run to about 100
  characters. Neither reference goes past about 65. Long measure is the single largest
  reason our pages look unfinished, and it is free to fix.

## What is measurably wrong on our own pages

- **Teams row.** The left column holds three lines of different sizes; the right column
  holds a toggle with a text button beneath it. Neither column shares a baseline with
  the other, and the pause control is a second line of prose where the toggle is a
  control, so the row has two right edges.
- **Team detail header.** "Lineup checks" and its toggle, then "Pause for the rest of
  the fantasy day" indented beneath the toggle, then a bold link. Three levels of
  hierarchy for one idea, none aligned.
- **Owner note.** Five layers of chrome around one text box: a heading, a help
  paragraph, the box, "Up to 2,000 characters", a character counter, a warning, the
  save button, and a second identical warning below the button. The help text wraps at
  about 430px inside a 1150px column because it sits in a narrow grid cell.
- **Roster.** Twenty players, each with a position, a team, and an adds and drops line.
  It restates what the provider already shows and what the run summary already
  explains.

## The fix, in two tracks

### Track A: content and structure, independent of any redesign

These are unambiguous and can land without deciding the visual language:

- Product copy stops naming a provider. Provider names remain only where a specific
  connection or team is named.
- Teams gain the fantasy league name and a provider jump out, both produced by the
  provider adapter so the page stays neutral.
- The pause control becomes an icon button beside the toggle, with the sentence in its
  tooltip, on both pages.
- Recent activity moves to the top of team detail.
- The roster section and the code that exists only to serve it are deleted. The
  provider roster read stays: the solver and the write path depend on it.
- The owner-note warning, the credential shaped validation, and the redundant
  character line are removed.
- "Report a problem with this team" prefills the feedback form with the team.

### Track B: a design language with rules

Not a reskin. A small set of rules that make every screen look decided:

1. **Measure.** 720px for anything meant to be read. 1120px maximum page width. Stats
   and lists may use the wider column only when they are tabular.
2. **Type.** Three sizes for text (13px labels in caps with 0.08em tracking, 16px body
   at 1.55, 20px lead), two for titles (28px and 40px). Tabular numerals wherever a
   number is compared to another number.
3. **Rules, not boxes.** Hairlines separate rows and sections. Cards lose their borders
   entirely. A surface earns a border only when it is a form control.
4. **Alignment.** One left edge for text, one right edge for controls. Controls sit on a
   28px square baseline so a toggle, an icon button and a link share a line.
5. **One emphasis per view.** A single solid element carries the action. Everything else
   is ink, rule, or the one accent.
6. **Identity survives.** Royal violet and gold stay. One mark or illustration earns a
   place on the landing page rather than many small flourishes.

## Order

Track A first, because it removes work that Track B would otherwise restyle. Track B is
prototyped against the real Teams and team detail screens and reviewed before it lands
anywhere else.
